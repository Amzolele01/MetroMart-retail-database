# MetroMart — Retail Database Project

An end-to-end retail data management and analysis project using PostgreSQL, SQL, and spreadsheet-based data investigation.

The project simulates a real-world retail database assignment, covering data discovery, profiling, data quality investigation, data cleaning, relational database development, SQL analysis, and business reporting.

---

## 1. Project Overview

MetroMart is a fictional retail business used as the basis for an end-to-end data project.

The project focuses on transforming raw retail datasets into reliable, structured, and meaningful data that can support business operations and decision-making.

The work follows a structured data workflow, beginning with understanding and investigating the source data before progressing towards database development and analytical reporting.

## 2. Project Objectives

The main objectives are to:

- Investigate and understand raw retail datasets.
- Assess data completeness, consistency, accuracy, and integrity.
- Identify and document data quality issues.
- Apply appropriate data cleaning and validation techniques.
- Design and implement a relational database using PostgreSQL.
- Develop SQL queries for data retrieval, transformation, and analysis.
- Generate meaningful business insights through data analysis.
- Document the complete development and investigation process.

## 3. Project Scope

The project covers the following areas:

- Retail data discovery and profiling.
- Data quality assessment and investigation.
- Data cleaning and validation.
- Relational database design and implementation.
- SQL querying and data analysis.
- Business reporting and documentation.

## 4. Project Workflow

The project is divided into structured phases to maintain a traceable and organised development process.

| Phase | Description |
|---|---|
| Phase 1 | Project Discovery |
| Phase 2 | Data Profiling |
| Phase 3 | Data Quality Investigation |
| Phase 4 | Data Cleaning and Validation |
| Phase 5 | Database Development |
| Phase 6 | SQL Analysis and Business Reporting |

Each phase has dedicated documentation and supporting evidence.

## 5. Repository Organisation

The repository is organised by project phase and supporting documentation.

Each phase contains relevant reports, investigation findings, technical documentation, scripts, and other project evidence.

The repository structure will expand as the project progresses.

## 6. Tools and Technologies
