# Client Source Package

## 1. Overview

This directory contains the original source materials supplied for the MetroMart Retail Database Project.

The client package provides the initial business context, project requirements, operational datasets, supporting reference files and historical notes required to understand and investigate the supplied data.

These materials form the original evidence base for the project's discovery, data profiling, quality investigation and subsequent database development activities.

## 2. Directory Structure

The client source package is organised into four directories:

| Directory | Description |
|---|---|
| [00_CLIENT_BRIEF/](./00_CLIENT_BRIEF/) | Contains the original client brief, business requirements and initial data dictionary. |
| [01_RAW_DATA/](./01_RAW_DATA/) | Contains the seven original operational datasets supplied for investigation and transformation. |
| [02_REFERENCE_FILES/](./02_REFERENCE_FILES/) | Contains supporting product category and store-code reference files. |
| [03_CLIENT_NOTES/](./03_CLIENT_NOTES/) | Contains informal historical system notes and the client's introductory project instructions. |

## 3. Source Material Classification

The supplied materials are grouped according to their purpose:

- **Client documentation:** Establishes the business context, project expectations and original business requirements.
- **Operational datasets:** Contains the customer, employee, product, store, sales and returns information used throughout the project.
- **Reference files:** Provides additional information for interpreting and validating selected operational data.
- **Client notes:** Provides historical context, potential data-quality concerns and instructions for handling the supplied package.

## 4. Data Preservation and Handling

The original client-provided files are retained in their supplied form.

The following principles apply throughout the project:

- Original raw datasets must not be modified.
- Data profiling, investigation, cleaning and transformation must use separate working copies.
- Not every inconsistency should automatically be treated as an error.
- Assumptions, validation findings and transformation decisions must be documented.
- Traceability between transformed records and their original sources should be maintained wherever practical.

## 5. Project Usage

This directory serves as the permanent reference archive for the original client materials.

The files are used to establish project requirements, understand the available data, investigate data-quality issues and support decisions made during subsequent project phases.

The archive also allows project reviewers to examine the original source material and understand the basis for the project's findings and implementation decisions.

## 6. Source Integrity

The contents of this directory represent the original materials received for the project. Any revised definitions, investigation findings, cleaned datasets or additional documentation produced during the project must be maintained separately from this archive.
